What I've shipped

Code in public, state stated plainly.

The work is on GitHub. Each item says what it is and where it stands.

01 · the engine

Tessera

A C++ fork of llama.cpp that takes calibration seriously: per-tensor evolutionary calibration (T640), native speculative decoding (DFlash / DSpark), and Apple Neural Engine prefill via Core ML on M-series Macs. The runtime's outputs are replayable to the reference.

github.com/Tribunus-dev/tessera · brief

02 · the app

Tessera Studio

The Swift desktop app that ships Tessera to users: a real agent loop with capability-scoped tools, manifest-based skills (SKILL.md), and a local-first file system. The macOS design is driven by a full Human Interface Guidelines study.

tessera.tribunus.dev · source

03 · the substrate

Calibration & telemetry tooling

The Python quantizer and schema-versioned telemetry that feed drafter training: per-tensor genetic search, MAP-Elites regime routing, AWQ and outlier policy, and per-step spec-decoding records (llama.tessera.spec.v1).

tessera/tools

Prism Engine

An inspectable heterogeneous AI deployment system in Rust — constitutional ECS, one canonical reality, immutable evidence, rebuildable projections. Open research surface; not in Tessera's shipping path.

How I work

Six rules I actually run on.

Not aspirations — the operating system. They apply to the codebase, the company, and this website.

→ Research first.

Deep-research passes and long design docs before code. The plan is downstream of the evidence, always — when they disagree, the research wins.

→ The real build is the gate.

Commits land at a SHA where the actual build is green — not a script that claims to be one. The ratchet only moves forward.

→ Records, not vibes.

Runs keep replayable records — what loaded, what quantized, what executed. If it can't be replayed, it doesn't count.

→ Replace, don't coexist.

No v1/v2/v3 copies in the same tree. Refactor in place; the version is a release tag, not a label on the code.

→ Local-first, no lock-in.

Self-hosted open source first. External accounts, keys, and APIs are design risks to engineer out — never inherited by default.

→ AI helps, humans own.

I use agents heavily — but every line ships under my name, and I can explain all of it. The agent drafts; the architect owns.

Background

How I got here.

I founded Tribunus in October 2024 in San Francisco, with one conviction: the inference and agent stack should be compiled, not improvised — planned, recorded, and replayable, rather than assembled at runtime. The company is the operational expression of that view, and Tessera Studio is its first product.

Before Tribunus I worked as a software engineer in the Bay Area, and before that as a freelance photographer and designer. That background shows up in the work — the care taken with typography, documentation, and the shape of every screen in Tessera Studio. It's the same discipline, applied to different surfaces.

I am currently building one product — Tessera Studio — as the sole maintainer of both the Swift app and the C++ engine underneath it. I am the only full-time person, and I intend to keep it that way until the product earns a team.

"I am one founder, doing one product, and I am not going to ship it badly." — Julian Torres, founder of Tribunus
